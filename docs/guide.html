Install

You need Orca 1.4.248 or newer (that is the engines.orca range in the plugin's manifest).

orca plugin install Lilykos/orca-the-lobby

This command installs the newest tagged release from this repository.

  1. Run the command above. Because the plugin runs code, Orca stops before writing anything, lists what it would be granted along with the publisher and repository, and prints the exact command to re-run with --approve <fingerprint>.
  2. Read the capabilities (what each is for), then re-run that command to approve. The approval is bound to this plugin, version, files and access.
  3. Open The Lobby from Orca's right sidebar. The status bar item Lobby also counts working agents and agents that need you.

The plugin is plain TypeScript and HTML that Orca loads directly; there is no build step.

Update with orca plugin update and remove with orca plugin uninstall. The plugin keeps its data only in Orca's per-plugin storage.

Using the panel

The panel has four views: Attention, Office, Activity and Settings. One search box and project filter are shared by the three functional views.

Attention and Reviewed

  • Compact rows put the task title first. Activate it to open details; use the separate Open agent action to navigate when available. If navigation is unavailable, the task still opens details and explains why.
  • Needs input contains currently blocked agents; Failed to review contains explicit failure outcomes; the native Finished · N disclosure counts eligible results while collapsed. Search reveals matching Finished results; clearing search restores your previous disclosure choice.
  • Waiting, quiet, cancelled, interrupted and unconfirmed states are not promoted to success or failure. Missing outcomes are labeled unknown. Mark Reviewed is an explicit result-drawer action for that completion only; it does not mark Orca's result read, change the agent or send terminal text. Markers expire after 24 hours and storage retains at most 500 completion keys.
  • Search is literal and case-insensitive over reported task/prompt, friendly name, provider and known project/workspace/branch/host labels. The native Filter disclosure shows an active-filter count; Clear remains visible while a filter restricts results. Filters are shared with Office and Activity, which keeps reported chart ancestors needed to locate matching agents.
  • Quiet states distinguish no live agents, no filter matches and no current intervention. A nonzero Finished count remains visible alongside working count. A saved-office capacity error is logged rather than truncating required identity data.

Completion identity prefers source finish time and reported turn/session identifiers. When those are missing, The Lobby persists the identity of its local observation. If Orca omits every discriminator and an entire new turn happens while unobserved in the same pane, it cannot be distinguished reliably from the previous turn. A source finish is labeled “Finished”; a local timestamp is labeled “Done observed”.

Project mute and reminder snooze

Open Settings → Notifications for alert preferences, project mute and current-episode reminders.

  • Mute a project to pause all The Lobby notifications for it. Agents remain visible and counted, and this does not change Orca's own notification settings.
  • Snooze an eligible blocked/quiet episode's reminder for 15 minutes, 1 hour or until resumed. The displayed expiry is absolute. Snooze affects reminders only; a later transition or episode is treated separately.
  • Unmuting or resuming does not send missed alerts later. Eligible transition alerts are grouped by project and kind for two seconds from the first event; one event keeps its individual message and a burst becomes one count summary.
  • Policy storage allows up to 200 muted projects, 500 snoozes and 1,000 handled identities within 200,000 serialized bytes. Read and write errors stay visible with a retry; an unsuccessful write is not shown as saved.

Office

  • Click a room sign to open or close its agent area. Rooms follow the order of Orca's sidebar. Point at a room and press ↑ or ↓ to set your own order, shared with Activity; Settings has Use the sidebar order again.
  • The list leads with the conversation title, an explicitly labelled prompt excerpt, or “Task not reported”, and shows the provider beside a friendly name. Activity keeps the original workspace and conversation title.
  • Up to four finished agents stand around the coffee machine; fewer in a narrow room.
  • Under each room is today's token count for that workspace.
  • Use the shared search and project filter to find an agent. Comfortable and Compact density are in Settings; Compact reduces spacing and secondary detail.

Activity

  • Pan wide charts with a trackpad swipe, Shift + wheel, ← →, or by dragging the background. Reset view recentres.
  • All / Needs attention switches the highlighting. Your selection, scroll position and collapsed branches survive the switch.
  • A child without an exact matching agent id opens a drawer with its reported state, operation and description, and no invented chat or workspace link. An agent whose reported parent is not in the roster stays unlinked with a short note; no parent is guessed.

The drawer

  • The drawer puts task, state, result and available primary action first. Open More details for calls, tokens and supplemental metadata; this disclosure stays open through live updates.
  • Go to agent switches to the agent's terminal. For an Orca chat session it opens the workspace and says that it did.
  • The instruction box (terminal agents only, not for finished agents) sends your text to that terminal. If another agent resolves to the same terminal, typing is refused so it cannot reach the wrong one. Instructions can be up to 8,000 characters.
  • Compact conversation asks for confirmation, then types /compact. Only for Claude Code, where it was tried.
  • A draft and the last result are dropped when the drawer closes.

What it reads, exactly

No telemetry. The plugin makes no direct network requests. Orca uses its existing connections to list agents on your paired servers.

Roster and events (from Orca)

The worker uses orca worktree ps --json for the cross-worktree roster: workspace and project names, state, prompt, current operation, helpers and linked items. It also asks Orca's agents.list for the focused workspace when focus changes, and listens for status changes and tool calls. It polls every three seconds while an agent is working and every twenty seconds when idle.

Paired servers have separate rooms labeled with the server name; local rooms say local. Unreachable paired servers disappear until they reconnect. Go to agent can navigate to a remote terminal or worktree, but remote file/log details, sending instructions and Compact are unavailable.

Tokens today (from local logs)

Claude Code session files under ~/.claude/projects/<workspace>/ and Codex session files under ~/.codex/sessions/ (matched by their recorded working folder). Only usage numbers and model ids are read. Each file is read once, then only what is appended. Counts are per workspace and project for the local day.

Per-agent context (an exact id chain)

Never from titles, times or folders:

  1. A chat agent's pane key is structured-agent-session-<Orca session id>:<leaf>.
  2. Orca's own session store (agent-session-domain.db on Orca 1.4.261+, or agent-session-journal.db on older versions), read-only through the sqlite3 macOS ships, records that session's Claude Code session id or Codex thread id. Only the provider and the session id are selected, never prompts or messages.
  3. That id is in the log's file name: ~/.claude/projects/*/<id>.jsonl or ~/.codex/sessions/YYYY/MM/DD/rollout-…-<id>.jsonl.

The drawer then shows the latest request's tokens (cache included), the compactions the log records, and the session's tokens today. For Codex that is the input side of the last request; output is left out. The percentage uses the window the log states: Codex does, Claude Code does not. Tokens today count only the agent's current provider session; an earlier one before a resume or /clear is not added.

The store is an Orca internal, not a documented API. If a future Orca changes it, these lines simply disappear. The read runs in the background and never holds up a panel update or a notification; the store is asked at most every 30 seconds per session and not again for a minute after a failure.

Other

  • Claude transcripts are read locally for titles and recent prompt text used in heuristic matching, plus TodoWrite entries and file names from edited paths for supplemental task lists and changed-file notes. Prompt text is not stored in the activity journal. Transcript model names are never attributed to an agent.
  • Git: git diff --shortstat HEAD for uncommitted changes.
  • Local journal: observed activity for up to 24 hours, oldest dropped first to fit the 200,000-byte serialized storage bound, never sent to the panel. It may hold clipped result or tool details; it does not store prompts.
  • Completion and review metadata: bounded identities let one completion stay reviewed across polling and restart. Reviewed keys are kept for 24 hours, capped at 500, and do not alter Orca's unread or status state.
  • Notification policy: local project mutes, episode snoozes and handled identities share the 200,000-byte serialized limit; caps are 200 mutes, 500 snoozes and 1,000 handled identities. A failed read/write is reported; a failed write is never acknowledged as saved.
  • No money estimate is ever made from tokens.

FAQ

What does Reviewed do?

It hides that completion from The Lobby's review queue after a successful local save. It does not clear Orca's unread flag or change agent status. Opening details or navigating does not review a result. Reviewed keys expire after 24 hours; at most 500 are retained.

What do mute and snooze change?

Project mute pauses all Lobby notifications for the selected project while its agents stay visible and counted. Episode snooze pauses repeat reminders for 15 minutes, 1 hour or until resumed; it does not suppress transition alerts. Neither changes Orca notification settings or sends catch-up alerts when cleared.

Why does a notification control show an error?

The worker could not read or save its bounded local policy. The panel keeps the error visible and offers a retry; a failed write is not treated as saved. The policy allows up to 200 muted projects, 500 snoozes and 1,000 handled identities within 200,000 serialized bytes.

When does the panel open to Attention or Office?

A genuinely new installation starts in Attention. A 1.2 upgrade, including one with existing office data but no preferences, starts in Office. The selected functional view is then remembered; Settings is not a startup view. Comfortable density is the migration default.

Why can't The Lobby always tell that a result is new?

It uses Orca's reported finish time and turn/session identifiers when available. Otherwise it keeps one local observation identity. If an entire new turn is hidden from observation and Orca reports no discriminator, identical pane and state data cannot prove that a new completion occurred.

Is it safe? Does it send my code or prompts anywhere?

No. It has no direct network code. It reads local files and runs the Orca CLI and Git on your machine. Orca uses its existing paired-server connections for remote roster and navigation requests. Prompts are not stored in its journal. The source is public.

Why can't I type into a chat agent?

Orca has no way for plugins to pick or type into a chat tab. The instruction box and Compact work for agents running in a terminal. For chat agents, Go to agent opens their workspace.

Can I approve or deny a blocked agent's request from the panel?

No. Orca does not report what a blocked agent is asking, and plugins have no approve / deny controls. The panel says Needs you and takes you to the agent.

Why does a Claude agent show tokens but no context percentage?

Claude Code's logs do not state the context window, and The Lobby will not guess one. Codex logs do, so Codex agents show a percentage.

The token total under a room differs from the number in the drawer.

The room total is per workspace for the whole local day. The drawer figure is for one agent's current provider session, so earlier sessions before a resume or /clear are not included.

Does it show which model an agent uses?

No. Orca's supported agent metadata reports the provider kind (Claude, Codex, Pi, …) but not the selected model, so the label next to a name is the provider.

Where do finished agents go?

They stand around the coffee machine (up to four drawn) and stay in the roster and Activity. Attention keeps eligible unread or newly observed results in the collapsed, counted Finished disclosure until you mark that completion Reviewed in The Lobby. Search reveals matching results; clearing search restores your disclosure choice. That local choice is separate from Orca's unread flag.

Why can I see a Finished count but not its rows?

Finished results start collapsed to keep the queue focused. Open the native disclosure to browse them, or search for a matching result; clearing search restores the disclosure choice you made. Collapsing the group does not change Reviewed state or notifications.

What are the colours?

Green is working, orange is Needs you, amber is waiting, red is failure, grey is done and blue is an unread result. Status pills appear on individual agents; there are no aggregate status chips.

Does it work on Windows or Linux?

The 1.2.0 release was validated on macOS. The 1.3.0 release has automated macOS fixture coverage, but its real GUI trial and independent Windows/Linux runtime checks remain outstanding. Windows CLI discovery was improved in 1.2.0. Per-agent context currently needs the macOS session-store path and sqlite3.

How do I get rid of the history it keeps?

Settings → Local data → Clear activity history, then confirm Clear. Cancel leaves the journal in place; it also expires after 24 hours.

Troubleshooting

The panel says “No agents to show yet.”

Start an agent in an Orca workspace; the roster refreshes every three seconds while something is working, every twenty seconds when idle. If agents are running and nothing shows, the Orca CLI may be unavailable to the plugin: it then falls back to status and tool-call events and the focused workspace's agent list, so only agents Orca has told it about appear, chat tool calls are unavailable, and finished agents linger for four hours.

An agent has no Context line.

It needs the exact id chain: a chat session (pane key structured-agent-session-…), Claude Code or Codex, on macOS, with sqlite3 available and Orca's session store readable. Agents in a plain terminal tab and other providers have no verified link and show nothing. After a failure (no sqlite3, a locked or missing database), or if the log is not found, it retries only once a minute.

Claude agents show no percentage.

Expected: Claude Code logs do not state a context window. You still get tokens.

Go to agent only opens the workspace.

That is what it does for Orca chat sessions, which have no terminal for a plugin to bring forward. The panel tells you when it happens.

The instruction box or Compact button is missing.

Controls that do not apply are left out. The box needs a terminal agent that is not finished, with its terminal found by the id or pane key Orca reports, and the terminal:send capability granted. If two agents resolve to one terminal, typing is refused. Compact is Claude Code only.

I got no stuck or needs-you notifications.

Check Settings: the switches and the stuck time (Off disables the alert), and that Orca may show notifications from the plugin. You get one stuck notification per quiet spell, not repeats.

Tool calls or file changes look incomplete.

Short chat tool calls can fall between polls; Orca does not yet report terminal tool calls on SSH or WSL hosts; and the changed-files count ignores new untracked files.

Everything is still, nothing moves.

Check Animate the office and your system's reduced-motion setting. The window still follows local time at period boundaries.

Still stuck? Open an issue with your Orca version and what the panel shows. Please leave out real prompts, paths and project names.
